# План работ и критерии приёмки

Пять этапов. Этап закрыт, когда `scripts/check_stage.ps1 <N>` возвращает код 0 и написан `docs/reports/stage<N>.md`. Пункты выполняются по порядку; отмечай их в `docs/PROGRESS.md`.

## Решения по умолчанию

Владелец может их поменять; до его слова действуют эти значения.

| Вопрос | Значение по умолчанию |
| --- | --- |
| Режим показа правок | «По нажатию»; в настройках доступны «Сразу», «В конце», «Выкл.» |
| Хранение аудио реплик | 30 дней; 0 отключает хранение |
| Голос собеседника | `af_heart`; выбор среди американских голосов Kokoro в настройках |
| Имя приложения | «Тренажёр», каталог данных `%LOCALAPPDATA%\EnglishTrainer`, пакет `trainer`, служба keyring `EnglishTrainer` |
| Уровень по умолчанию | B1; меняется в настройках |
| Менеджер окружения | `uv`, если ставится без прав администратора; иначе `venv` и `pip` |

## Целевые показатели

| Показатель | Цель | Где проверяется |
| --- | --- | --- |
| Распознавание реплики 10 с | до 0,4 с | этап 0, `scripts/bench.py` |
| Синтез первого предложения | до 0,3 с | этап 0, `scripts/bench.py` |
| От конца реплики до первого звука ответа | до 1,5 с с облачной LLM; с мок-LLM до 0,9 с | этапы 1 и 4, сквозной тест |

| Запуск приложения до готовности окна | до 20 с при тёплом кэше | этап 4 |

Если цель не достигается, это не блокирует этап: зафиксируй замер, причину и выбранный компромисс в отчёте этапа.

## Этап 0. Проверка железа и фиксация версий

Цель: доказать, что стек работает на этом ноутбуке, измерить его и закрепить версии. Кода приложения на этом этапе нет.

Задачи:

- **0.1 Каркас.** `git init`, структура каталогов (`trainer/`, `web/`, `tests/`, `scripts/`), `pyproject.toml`, ruff, pytest с маркерами `gpu`, `e2e`, `live`. Скрипты `setup.ps1`, `test.ps1`, `check_stage.ps1`, `run.ps1` (пока сообщает, что приложение не собрано).
- **0.2 Окружение.** Python 3.12. Сборка torch с CUDA, которая поддерживает RTX 5060: сверить по официальной странице установки PyTorch. faster-whisper с библиотеками cuBLAS и cuDNN 9: на Windows их нужно сделать видимыми процессу; сверить актуальный способ по странице проекта. Kokoro и espeak-ng. transformers для wav2vec2. Каталог моделей: `%LOCALAPPDATA%\EnglishTrainer\models` (`HF_HOME`).
- **0.3 Замеры.** `scripts/bench.py`: холодный и тёплый запуск распознавания на фразах 5 и 10 с; синтез первого предложения; занятая видеопамять по каждой модели и суммарно; петля «Kokoro читает 10 фраз → faster-whisper распознаёт» с подсчётом доли ошибок по словам.
- **0.4 DeepSeek.** По официальной документации выяснить: значение `thinking` по умолчанию для `deepseek-flash`, как отключить рассуждения, условия JSON-режима, формат потока. Записать в `docs/reports/deepseek.md` со ссылками на страницы. Живой запрос выполняется, только если ключ уже сохранён владельцем; иначе пункт переносится в `docs/HUMAN_TASKS.md` и не блокирует этап.
- **0.5 Уверенность слов.** Проверить, что faster-whisper отдаёт вероятность для каждого слова при `word_timestamps=True`. Если нет — выбрать замену (например, средняя вероятность сегмента) и записать решение.
- **0.6 Окно.** Проверить запуск `msedge --app=http://127.0.0.1:<порт>/ --user-data-dir=<каталог>`: окно без адресной строки, запрос микрофона появляется один раз и сохраняется в профиле. Проверить Playwright с каналом `msedge` и флагами фейкового микрофона из `docs/testing.md`.
- **0.7 Фонемная модель.** Загрузить `facebook/wav2vec2-lv-60-espeak-cv-ft`, вывести словарь фонем, сравнить с выводом espeak-ng `en-us` для 20 слов из `docs/data/reading_phrases.json`. Записать расхождения символов: они понадобятся на этапе 3.
- **0.8 Фиксация.** Lock-файл зависимостей. Отчёт `docs/reports/stage0.md`: таблица «показатель, цель, замер», версии, принятые отклонения.

Запасные пути, если основной не работает:

| Проблема | Порядок замен |
| --- | --- |
| faster-whisper не видит CUDA | `int8_float16` вместо `float16` → Whisper `turbo` через transformers на torch CUDA → whisper.cpp → faster-whisper на процессоре с моделью меньше |
| Kokoro не работает на видеокарте | Kokoro на процессоре → kokoro-onnx |
| Не хватает видеопамяти | Kokoro на процессор → фонемная модель грузится только в режиме «Чтение» и выгружается после → распознавание в `int8_float16` |
| espeak-ng требует прав администратора | Портативная установка в каталог данных → запись в `docs/HUMAN_TASKS.md` |

Критерии приёмки (`check_stage.ps1 0`):

- `torch.cuda.is_available()` истинно, имя устройства содержит `RTX 5060`.
- Петля TTS → STT: доля ошибок по словам не выше 10 % на 10 фразах.
- `docs/reports/stage0.md` и `docs/reports/deepseek.md` существуют; в первом заполнены все строки таблицы показателей.
- Lock-файл существует; `scripts/setup.ps1` повторно отрабатывает без ошибок.

## Этап 1. Разговор

Цель: рабочий диалог голосом в ручном режиме, правки на русском, окно API-подключений.

Задачи:

- **1.1 Запуск и защита.** Ядро FastAPI на случайном свободном порту `127.0.0.1`. Токен запуска: `GET /?t=<токен>` ставит cookie `HttpOnly; SameSite=Strict` и перенаправляет на `/`. Промежуточный слой проверяет cookie, `Host` и `Origin` на всех маршрутах и на WebSocket. Заголовок CSP запрещает внешние источники. Лаунчер открывает Edge в режиме приложения; ядро завершается, когда окно закрыто и соединение не восстановилось за 10 с.
- **1.2 Хранилище.** Схема SQLite из `docs/design.md`, раздел «Данные и хранение». Версионируемые миграции. Каталог данных создаётся при первом запуске.
- **1.3 Подключения.** HTTP-маршруты из `docs/protocol.md`. Ключ уходит в keyring, в базе остаются 4 последних символа. Ровно одно активное подключение. Удаление строки удаляет ключ. Проверка подключения: короткий запрос с замером задержки. Фильтр журналов вырезает всё, что похоже на ключ.
- **1.4 Клиент LLM.** Потоковый `chat/completions`, слияние «Доп. параметров» в тело запроса, тайм-ауты, отображение ошибок провайдера в коды из протокола. Шаблон DeepSeek учитывает выводы `docs/reports/deepseek.md`.
- **1.5 Речь.** Сервисы распознавания и синтеза за одной очередью задач видеокарты. Вход распознавания приводится к 16 кГц моно на стороне ядра. Разбиение потока LLM на предложения для синтеза; сокращения и числа не должны рвать предложение.
- **1.6 Оркестратор.** Состояния `idle → listening → transcribing → thinking → speaking`, протокол из `docs/protocol.md`, отмена ответа по `interrupt`, сообщение `timing` с замерами на каждую реплику. История для LLM: системный промпт и начало истории остаются побайтно стабильными между запросами, чтобы работал кэш контекста у провайдера; старые реплики сворачиваются в краткое резюме.
- **1.7 Корректор.** Промпт из `docs/prompts/corrector.md`, проверка JSON по схеме, один повтор при пустом или невалидном ответе, проверка `quote` как подстроки, сохранение правок и ключа ошибки.
- **1.8 Окно.** Экран «Разговор» по `docs/ui/main.html`: лента, пометки, карточка правок, режимы показа правок. Нижняя панель: волна, состояние, кнопка микрофона, Пробел и Esc. Экран «API-подключения» по `docs/ui/connections.html`. Шрифты локальные. Первый экран содержит кнопку «Начать разговор»: по её нажатию создаётся `AudioContext`, поэтому звук ответа не блокируется политикой автовоспроизведения.
- **1.9 Сценарии и история.** Сценарии из `docs/data/scenarios.json`. Собеседник открывает разговор первой репликой. Список прошлых сессий и просмотр ленты.

Критерии приёмки (`check_stage.ps1 1`):

- Набор `fast` зелёный: разбиение на предложения, схема корректора, проверка `quote`, хранилище, клиент LLM на мок-сервере (поток, 401, 429, тайм-аут), фильтр ключей в журнале.
- Тесты защиты: запрос без cookie отклонён; чужой `Origin` на WebSocket отклонён; чужой `Host` отклонён; ответы не содержат заголовков CORS.
- Тест секрета: после сохранения тестового ключа он не находится ни в файле базы, ни в журналах, ни в ответах HTTP.
- Набор `gpu` зелёный: реплика из WAV через WebSocket с мок-LLM даёт `user.transcript`, минимум одно `tutor.sentence` со звуком, `corrections`, `timing`.
- Набор `e2e` зелёный: с фейковым микрофоном Пробел начинает запись, волна показывает уровень выше порога, второй Пробел отправляет реплику, в ленте появляются текст реплики и ответ, панель проходит через `speaking`, карточка правок открывается по нажатию. Русский текст есть только в карточке.
- Сценарий «сбой подключения»: при ошибке 401 в ленте появляется сообщение с кнопкой переключения; автоматического переключения нет.
- В отчёте: замер «конец реплики → первый звук» на мок-LLM и, если ключ есть, на живом подключении.

## Этап 2. Удобство

Цель: автоматический режим реплик, помощники, итоги, память об ошибках, настройки.

Задачи:

- **2.1 Авто-режим.** Silero VAD в окне (файлы модели раздаёт ядро). Допустимая пауза 1–3 с, по умолчанию 1,5 с. Переключатель «Ручной / Авто» в панели.
- **2.2 Перебивание.** Пробел во время ответа останавливает звук и начинает запись. Перебивание голосом доступно только при включённом флаге «Я в наушниках».
- **2.3 Помощники.** «Подсказка», «Перевод», «Как сказать?», «Повторить», «Медленнее» по `docs/prompts/helpers.md`. Всё, что на русском, показывается только текстом.
- **2.4 Итоги сессии.** Промпт `docs/prompts/summary.md`: главный вывод, упражнение, полезные фразы. Экран «Итоги» по `docs/ui/summary.html`. Проверка упражнения голосом.
- **2.5 Повторяющиеся ошибки.** Счётчики по ключу ошибки, серия сессий без повтора, закрытие после трёх чистых сессий. От трёх до пяти самых частых ключей подставляются в системный промпт собеседника как «фокус практики».
- **2.6 Словарь.** Сохранение фраз из итогов, простое интервальное повторение, экран списка.
- **2.7 Настройки.** Разделы «Звук и голос» (устройство ввода и вывода, голос, скорость), «Разговор» (уровень, режим, пауза, повтор верной формы собеседником), «Правки», «Данные» (срок хранения аудио, экспорт JSON и CSV, «Удалить все данные»).
- **2.8 Smart Turn (необязательно).** Подтверждение конца реплики моделью Smart Turn v3 на процессоре за настройкой. Делается, только если 2.1–2.7 закрыты.

Критерии приёмки (`check_stage.ps1 2`):

- Запись с паузой 1,2 с внутри фразы при пороге 1,5 с остаётся одной репликой; при пороге 1,0 с делится на две.
- `interrupt` во время синтеза: поток LLM закрыт, очередь синтеза пуста, новых `tutor.sentence` нет; запрос корректора при этом завершился.
- Схемы ответов помощников и итогов проходят проверку; текст с кириллицей никогда не попадает в сервис синтеза (тест на уровне сервиса: такой вызов отклоняется).
- Счётчики ошибок: три сессии подряд с ключом `for_since` поднимают его в «фокус»; три сессии без него закрывают.
- Задача очистки удаляет аудио старше срока; «Удалить все данные» очищает базу и аудио и не трогает ключи без явного флажка.
- Сквозной тест авто-режима с фейковым микрофоном зелёный.

## Этап 3. Произношение

Цель: режим «Чтение» с оценкой звуков по американской норме, затем осторожные пометки в разговоре. Этап алгоритмически самый сложный; владельцу рекомендовано включить для него модель Fable.

Задачи:

- **3.1 Эталон.** Текст → фонемы espeak-ng `en-us` с границами слов; приведение символов к словарю модели по результатам пункта 0.7.
- **3.2 Акустика.** Вероятности фонем по кадрам от wav2vec2; модель грузится при входе в режим и выгружается при нехватке видеопамяти.
- **3.3 Выравнивание.** Принудительное CTC-выравнивание эталона по вероятностям; отрезок записи для каждой фонемы.
- **3.4 Оценка.** Goodness of Pronunciation для каждой фонемы; балл слова и фразы.
- **3.5 Диагноз.** Свободное распознавание фонем и сопоставление с эталоном (Нидлман — Вунш): что прозвучало вместо ожидаемого.
- **3.6 Пороги.** Три уровня: верно, неточно, ошибка. Поправка чувствительности по каждому звуку; кнопка «Это было верно» её сдвигает.
- **3.7 Советы.** Каталог `docs/data/l1_ru_catalog.json`: пара «ожидалось → прозвучало» даёт совет на русском. Американские допуски из `docs/design.md`.
- **3.8 Экран «Чтение».** По `docs/ui/reading.html`: фраза с разметкой, разбор слова, эталон голосом Kokoro, своя запись, статистика по звукам. Фразы из `docs/data/reading_phrases.json`. В этом режиме шумоподавление и автоусиление микрофона отключаются, если сравнение на записях покажет, что они ухудшают оценку.
- **3.9 Пометки в разговоре.** Оцениваются только слова с высокой уверенностью распознавания; в ленте подсвечиваются только уровни «ошибка» при строгом пороге; остальное идёт в статистику.

Критерии приёмки (`check_stage.ps1 3`), все на синтезированной речи:

- Ложные срабатывания: три американских голоса Kokoro читают все фразы из `reading_phrases.json`; уровень «ошибка» получают не более 3 % фонем.
- Подстановки: для минимальных пар из каталога (think/sink, west/vest, sing/sin, bad/bat, ship/sheep, then/den) синтезируется второе слово при эталоне первого; целевая фонема получает уровень «ошибка» не менее чем в 80 % случаев, и диагноз называет прозвучавший звук не менее чем в 60 %.
- Время оценки фразы 5 с не больше 1 с после конца записи.
- Отчёт `docs/reports/stage3.md` содержит обе метрики по каждому звуку и список звуков, где метод ненадёжен.

Ограничение метода проверки: синтезированные голоса не заменяют речь изучающего. Финальную калибровку на своём голосе делает владелец (см. `docs/HUMAN_TASKS.md`).

## Этап 4. Упаковка и регресс

Задачи:

- **4.1 Установка с нуля.** `scripts/setup.ps1` на чистой копии репозитория в другом каталоге доводит систему до рабочего состояния.
- **4.2 Запуск.** `scripts/run.ps1` и ярлык «Тренажёр» без окна консоли. Повторный запуск активирует уже открытое окно, второго ядра не появляется.
- **4.3 Эксплуатация.** Ротация журналов; понятные сообщения, если нет видеокарты, моделей или активного подключения; режим `HF_HUB_OFFLINE=1` в работе.
- **4.4 Сеть.** Тест перехватывает исходящие соединения ядра за полный сквозной сценарий: адреса только `127.0.0.1` и хост активного подключения.
- **4.5 Документация владельца.** `README.md`: установка, запуск, обновление, резервная копия, удаление.
- **4.6 Регресс.** Все наборы тестов; итоговый отчёт `docs/reports/final.md`: показатели против целей, известные ограничения, что осталось владельцу.

Критерии приёмки (`check_stage.ps1 4`): все наборы зелёные; тест сети зелёный; установка с нуля зелёная; ярлык создан и запускает приложение; `final.md` написан.
