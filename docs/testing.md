# Тестирование без человека

Цель: каждая проверка из `docs/PLAN.md` запускается командой и возвращает код завершения. Человек нужен только для оценки на слух и для живой речи (см. `docs/HUMAN_TASKS.md`).

Три приёма заменяют человека:

- **Речь** синтезирует Kokoro: готовые WAV-файлы служат и репликами пользователя, и эталоном для проверки распознавания.
- **Микрофон** в сквозных тестах заменяет WAV-файл, который Edge подаёт как устройство ввода.
- **LLM** заменяет локальный мок-сервер с OpenAI-совместимым интерфейсом.

## Наборы

| Набор | Маркер pytest | Что нужно | Что проверяет | Время |
| --- | --- | --- | --- | --- |
| `fast` | без маркера | Только Python | Логика без моделей: протокол, хранилище, клиент LLM на моке, защита, разбиение на предложения, схемы | до 1 мин |
| `gpu` | `gpu` | Видеокарта и модели | Распознавание, синтез, реплика через WebSocket с мок-LLM, оценка произношения | до 10 мин |
| `e2e` | `e2e` | Edge, Playwright, видеокарта | Окно целиком с фейковым микрофоном и мок-LLM | до 10 мин |
| `live` | `live` | Сохранённый ключ и сеть | Живой провайдер: поток, JSON-режим, качество корректора | до 3 мин |

`scripts/test.ps1 <набор>` запускает набор; `all` запускает `fast`, `gpu`, `e2e` и, если есть активное подключение с ключом, `live`. Набор `live` при отсутствии ключа пропускается с пометкой `skipped`, а не падает.

Набор `live` тратит деньги владельца: не больше 80 запросов за запуск, без повторов в цикле. Запускай его один раз при закрытии этапа и после изменения промптов.

## Изоляция от данных владельца

Тесты никогда не работают с настоящим каталогом данных и настоящими ключами.

| Переменная окружения | Назначение | Значение в тестах |
| --- | --- | --- |
| `TRAINER_DATA_DIR` | Каталог данных | Временный каталог теста |
| `TRAINER_KEYRING_SERVICE` | Имя службы в keyring | `EnglishTrainer-test` |
| `TRAINER_MODELS_DIR` | Каталог моделей | Общий настоящий каталог: модели не скачиваются заново |

Это обычная конфигурация, а не обход защиты. Запрещены маршруты, флаги и переменные, которые отключают проверку cookie, `Origin` и `Host`, подставляют текст вместо распознавания или иначе меняют поведение ядра «только для тестов».

Набор `live` читает ключ из настоящей службы keyring только для чтения и не выводит его.

## Речевые фикстуры

`tests/fixtures/make_fixtures.py` синтезирует WAV-файлы и кладёт их в `tests/fixtures/audio/generated/` (каталог не хранится в git). Список — в `tests/fixtures/phrases.json`. Генерация детерминирована настолько, насколько это позволяет Kokoro; файл пересоздаётся, только если его нет.

Минимальный состав:

| Файл | Содержимое | Для чего |
| --- | --- | --- |
| `loop_01` … `loop_10` | 10 фраз длиной 3–10 с, голос `af_heart` | Петля TTS → STT, доля ошибок по словам |
| `turn_basic` | «I have worked on this project since two years.» и 5 с тишины в конце | Сквозной тест ручного режима |
| `turn_pause_1200` | Фраза, 1,2 с тишины, вторая фраза, 5 с тишины | Проверка порога паузы в авто-режиме |
| `silence_5s`, `noise_5s` | Тишина и розовый шум | Пустое распознавание |
| `too_short` | 0,2 с речи | Код `audio_too_short` |
| `read_<phrase_id>_<voice>` | Каждая фраза из `reading_phrases.json` тремя американскими голосами | Ложные срабатывания оценки произношения |
| `pair_<expected>_<actual>` | Минимальные пары из каталога: синтезируется второе слово | Обнаружение подстановок |

Формат для фейкового микрофона: WAV, PCM 16 бит, моно, 48 кГц. Для запросов к ядру напрямую годится 24 кГц от Kokoro: ядро само приводит частоту.

Доля ошибок по словам считается после нормализации: нижний регистр, без пунктуации, числа словами. Библиотека `jiwer` или собственная функция на расстоянии Левенштейна.

Ограничение: синтезированная речь чище живой. Замеры на ней показывают, что конвейер работает, но не заменяют проверку на голосе владельца.

## Мок LLM

`tests/mock_llm/` — отдельное приложение, которое фикстура pytest поднимает на свободном порту `127.0.0.1`. Тест создаёт подключение с адресом `http://127.0.0.1:<порт>/v1` и тестовым ключом вида `sk-test-<случайная строка>`.

Маршрут `POST /v1/chat/completions`:

- При `stream: true` отвечает потоком SSE в формате OpenAI: строки `data: {...}` с `choices[0].delta.content`, в конце `data: [DONE]`. Текст делится на куски по 2–3 слова с настраиваемой задержкой.
- При наличии `response_format` отвечает JSON-объектом. Для корректора мок строит правку из самой реплики: `quote` — первые два слова текста пользователя, поэтому проверка подстроки проходит при любом распознавании.
- Проверяет заголовок `Authorization: Bearer <тестовый ключ>`; при несовпадении отвечает 401.
- Записывает все полученные запросы: тест читает их через `GET /__mock/requests` и проверяет состав тела (нет звука, есть `extra_params`, стабильное начало `messages`).

Управление поведением — `POST /__mock/script`: задержка первого куска, задержка между кусками, текст ответа, код ошибки (401, 429, 500), обрыв потока на N-м куске, пустой ответ, невалидный JSON, зависание до тайм-аута. Эти маршруты есть только у мока; у ядра их нет.

## Сквозные тесты: Edge и фейковый микрофон

Playwright для Python, канал `msedge`, постоянный профиль во временном каталоге. Флаги Chromium:

```text
--use-fake-device-for-media-stream
--use-fake-ui-for-media-stream
--use-file-for-fake-audio-capture=<абсолютный путь>.wav
```

Что нужно знать (проверь на этапе 0.6 и запиши результат в отчёт):

- Файл задаётся при запуске браузера и по умолчанию проигрывается по кругу. Один файл — один экземпляр браузера; тесты с разными файлами запускают браузер заново.
- Суффикс `%noloop` после пути отключает повтор; проверь, что он работает в установленной версии Edge.
- Второй флаг снимает диалог разрешения микрофона. В настоящем запуске диалог остаётся; его один раз принимает владелец.
- Автовоспроизведение: тест нажимает «Начать разговор» так же, как человек; флаг `--autoplay-policy` не используется.
- Сначала пробуй режим headless. Если в нём не работает захват или воспроизведение, запускай с окном и запиши это в «Решения».

Синхронизация с зацикленным файлом в ручном режиме: тест ждёт, пока уровень на волне опустится ниже порога тишины на 1 с, нажимает Пробел, ждёт подъёма и нового спада уровня на 1 с, нажимает Пробел. Так в запись попадает ровно одна фраза.

В авто-режиме при выключенном флаге «Я в наушниках» окно не начинает новую реплику, пока ядро в состоянии `thinking` или `speaking`; следующая петля файла станет следующей репликой. Тест завершает сессию после нужного числа реплик.

Тест запускает приложение тем же лаунчером, что и владелец, но браузер открывает сам: лаунчер получает параметр `--no-window` и печатает адрес с токеном в стандартный вывод. Это единственное отличие от обычного запуска; защита при этом работает полностью.

## Наблюдаемость окна

Тесты смотрят на те же атрибуты, которыми пользуется вёрстка. Отдельных тестовых интерфейсов нет.

| Атрибут | Где | Значения |
| --- | --- | --- |
| `data-state` | Корневой элемент нижней панели | `idle`, `listening`, `transcribing`, `thinking`, `speaking` |
| `data-level` | Элемент волны | Текущий уровень сигнала от 0 до 100, обновляется не реже 10 раз в секунду |
| `data-source` | Элемент волны | `mic` или `tutor` |
| `data-testid` | Интерактивные элементы и блоки ленты | `start-session`, `mic-button`, `mode-toggle`, `turn-user`, `turn-tutor`, `correction-mark`, `correction-card`, `pron-mark`, `error-banner`, `switch-connection`, `conn-row`, `conn-add`, `conn-key-input`, `conn-test`, `conn-activate`, `conn-delete` |
| `data-turn-id` | Блок реплики | Идентификатор реплики |
| `data-first-audio-ms` | Блок реплики собеседника | Время от конца реплики до первого звука по часам окна |
| `lang` | Каждый текстовый блок | `en` для реплик, `ru` для правок и подсказок |

Проверка «русский только в карточках»: в элементах с `lang="en"` нет кириллицы; в сервис синтеза кириллица не приходит (отдельный тест уровня сервиса).

## Проверки защиты

Набор `fast`, без моделей:

- Запрос к `/api/health` без cookie → `401`. С cookie и `Host: evil.example` → `421`. С `Origin: http://evil.example` → `403`.
- Рукопожатие WebSocket без cookie, с чужим `Origin`, с чужим `Host` → отказ.
- Повторное использование токена запуска → `403`.
- Ни один ответ не содержит заголовков `Access-Control-*`.
- HTML отдаётся с заголовком CSP; в файлах `web/` нет адресов `http://` и `https://`, кроме комментариев с лицензиями.
- **Секрет.** Тест сохраняет подключение с ключом-маркером, проводит реплику и проверку подключения с ошибкой 401 от мока, затем ищет маркер в файле базы, журналах, экспорте, ответах всех маршрутов `GET` и в стандартном выводе ядра. Маркер должен находиться только в keyring службы `EnglishTrainer-test` и в запросах, которые записал мок.
- **Сеть** (этап 4). Тест перехватывает создание соединений в процессе ядра за полный сценарий и сверяет адреса: только `127.0.0.1` и хост активного подключения. В тесте активное подключение — мок, поэтому любой внешний адрес означает провал.

## Замеры задержки

Точки замера совпадают с полями сообщения `timing` из `docs/protocol.md`. Окно добавляет свою: от отправки `turn.audio` до начала воспроизведения.

- На мок-LLM с задержкой первого куска 0 мс получается собственная задержка приложения: цель до 0,9 с.
- На мок-LLM с задержкой 500 мс получается приближение к облачному провайдеру: цель до 1,5 с.
- Каждый замер повторяется 5 раз; в отчёт идут медиана и максимум. Первый прогон после загрузки моделей в расчёт не входит и записывается отдельно как холодный.

## Качество корректора (набор `live`)

`docs/data/corrector_eval.jsonl` — фразы с ожидаемым результатом. Тест прогоняет их через настоящий промпт и активное подключение.

| Метрика | Порог |
| --- | --- |
| Ответ проходит проверку схемы (с одним повтором) | 100 % |
| `quote` является подстрокой реплики | не ниже 95 % правок |
| Верные фразы (`expect: []`) остаются без правок | не ниже 80 % фраз |
| В фразе с ошибкой найден ожидаемый ключ `pattern` | не ниже 70 % фраз |
| Слова из `low_conf` не попадают в `quote` | 100 % |
| `note_ru` написан кириллицей и не длиннее 25 слов | 100 % |

Если порог не достигнут, правится промпт в коде, а результат и изменённый текст фиксируются в отчёте этапа. Без ключа эта проверка откладывается и записывается в `docs/HUMAN_TASKS.md`.

## Приёмка этапа

`scripts/check_stage.ps1 <N>` делает три вещи: запускает наборы, нужные этапу и всем предыдущим этапам; проверяет, что существуют отчёты и в них нет незаполненных строк; печатает сводку и возвращает 0 только при полном успехе. Пропущенный по причине отсутствия ключа набор `live` не считается провалом, но попадает в сводку отдельной строкой.
