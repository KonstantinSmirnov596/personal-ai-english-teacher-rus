# Голосовой тренажёр американского английского

Персональное десктоп-приложение для Windows: разговорная практика с ИИ-собеседником, правки на русском, оценка произношения. Один пользователь, один компьютер (Acer Nitro V17 AI: Ryzen 7 260, 16 ГБ ОЗУ, RTX 5060 Laptop 8 ГБ).

Документы проекта:

- `docs/design.md` — архитектура и решения. Источник истины по тому, ЧТО строим.
- `docs/PLAN.md` — этапы, задачи, критерии приёмки. Источник истины по ПОРЯДКУ и по тому, когда этап закрыт.
- `docs/protocol.md` — контракт WebSocket и HTTP между окном и ядром.
- `docs/testing.md` — как тестировать без человека (петля TTS → STT, фейковый микрофон, мок LLM).
- `docs/prompts/`, `docs/data/` — исходные промпты и данные; при реализации переносятся в код и дальше правятся там.
- `docs/ui/` — статичные макеты экранов и токены оформления.

## Каждая сессия

1. Прочитай `docs/PROGRESS.md`: текущий этап, что сделано, открытые вопросы.
2. Продолжай с первого незакрытого пункта `docs/PLAN.md`.
3. После каждого закрытого пункта и в конце сессии обнови `docs/PROGRESS.md`.

## Режим работы: автономно

- Решения внутри этапа принимай сам. Каждое нетривиальное решение записывай в `docs/PROGRESS.md`, раздел «Решения»: что выбрано и почему, одной-двумя строками.
- Пункт плана закрыт, только когда его проверка запущена и прошла. Не отмечай выполненным то, что не запускалось.
- Этап закрыт, когда `scripts/check_stage.ps1 <N>` завершился с кодом 0 и написан отчёт `docs/reports/stage<N>.md`. После этого сразу переходи к следующему этапу.
- К человеку обращайся только по списку из `docs/HUMAN_TASKS.md` и перед действиями вне папки проекта. Исключения, на которые разрешение не нужно: установка зависимостей в окружение проекта, загрузка моделей в каталог данных приложения.
- Вопросы копи: записывай в `docs/HUMAN_TASKS.md` и задавай одним сообщением в конце этапа. Пока ждёшь ответа, делай то, что не заблокировано.
- Если проверка не проходит после трёх разных подходов, запиши в `docs/PROGRESS.md`, что пробовал и что видел, и переходи к независимым задачам. Проверку ослаблять или удалять нельзя; изменить критерий можно только с записью причины в «Решения».
- При противоречии между документами выбирай вариант, который не нарушает раздел «Жёсткие ограничения», и запиши противоречие в «Решения».

## Жёсткие ограничения

- Наружу уходят только HTTPS-запросы к base URL активного подключения LLM. В работающем приложении нет телеметрии, CDN, внешних шрифтов и скриптов. Пакеты и модели скачиваются только при установке.
- Звук не покидает компьютер: распознавание, синтез и оценка произношения работают локально.
- Ключи API хранятся только в Windows Credential Manager через `keyring`. Ключ не попадает в файлы, базу, логи, тесты, git, вывод команд и сообщения чата. В окно возвращаются только 4 последних символа.
- Ключ у владельца не запрашивается в чат. Он вводит его сам в окне «API-подключения».
- Локальный сервер слушает только `127.0.0.1`, требует токен запуска, проверяет `Origin` и `Host` для HTTP и WebSocket, CORS не включает.
- Собеседник говорит только на американском английском. Русский текст существует только в интерфейсе (правки, пояснения, подсказки) и никогда не уходит в синтез речи.
- Ответы LLM вставляются в DOM как текст (`textContent`); JSON от LLM проверяется по схеме.
- Тестовых «чёрных ходов» в ядре нет. Тесты наблюдают состояние через обычные атрибуты интерфейса (`data-state`, `data-testid`).

## Стек

Версии закрепляет этап 0; до него это целевые значения, а не факты.

- Python 3.12, FastAPI и uvicorn в одном процессе, SQLite, httpx для LLM (OpenAI-совместимый `POST {base_url}/chat/completions`, поток SSE).
- Распознавание: faster-whisper, модель `turbo`, `float16`, CUDA. Синтез: Kokoro, `lang_code='a'`. Произношение: `facebook/wav2vec2-lv-60-espeak-cv-ft` и espeak-ng `en-us`.
- Окно: статический фронтенд без этапа сборки (HTML, CSS, ES-модули). Открывается в Edge с флагом `--app` и отдельным `--user-data-dir`.
- Тесты: pytest; сквозные — Playwright с каналом `msedge` и фейковым микрофоном.
- Данные приложения: `%LOCALAPPDATA%\EnglishTrainer` (база, аудио, модели, журналы, профиль Edge). В репозитории данных нет.

## Проверяй, а не вспоминай

Версии пакетов, флаги и параметры API меняются. Перед тем как закрепить версию или опереться на параметр, сверься с официальной документацией, `--help` или фактическим запуском. Обязательно для: параметра `thinking` у DeepSeek, библиотек CUDA 12 и cuDNN 9 под Windows, сборки torch под RTX 5060, поля уверенности слова в faster-whisper, флагов Chromium для фейкового микрофона, словаря фонем модели wav2vec2.

## Команды

Точки входа создаёт этап 0 и держит рабочими:

- `scripts/setup.ps1` — окружение, зависимости, модели. Повторный запуск безопасен.
- `scripts/run.ps1` — запуск приложения.
- `scripts/test.ps1 fast|gpu|e2e|live|all` — наборы тестов.
- `scripts/check_stage.ps1 <N>` — приёмка этапа: запускает нужные наборы и проверяет наличие отчёта.

## Код

- Идентификаторы и комментарии в коде на английском. Все строки интерфейса на русском, в одном файле `web/i18n/ru.js`.
- Аннотации типов везде; сообщения протокола и ответы LLM описаны pydantic-моделями; `ruff check` и `ruff format` чистые.
- В закрытых пунктах нет заглушек и `TODO: implement`.
- Коммит после каждого закрытого пункта плана: `stage<N>: <что сделано>`. `git push` не выполнять.

## Compact Instructions

При сжатии контекста сохрани: номер текущего этапа и пункта плана, список непройденных проверок с последними ошибками, решения и вопросы к человеку, ещё не записанные в `docs/PROGRESS.md` и `docs/HUMAN_TASKS.md`.
